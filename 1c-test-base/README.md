# Тестовая база 1С и расширение amoCRM

> Актуальный комплект с исправлением цены и договора: `extension/price-contract-fix`.
> Общая документация: [README проекта](../README.md), [правила расчёта](../docs/BUSINESS-RULES.md), [проверки и ограничения](../docs/VALIDATION.md).
> Разделы ниже описывают исходный снимок и этап исправления номенклатурной группы; они не заменяют документацию нового варианта.

Снимок тестовой базы от **26.10.2026**, подготовленный для приватного репозитория `kringetos/1cToAmoWidget`.

## Файлы

- `InfoBase26-2026-10-26.dt.part001`–`part003` — штатная выгрузка информационной базы, разбитая на части до 1 ГиБ; хранится через Git LFS.
- `Restore-Dump.ps1` — сборка частей обратно в `.dt` с проверкой SHA-256.
- `extension/ИнтеграцияAmoCRM_исправление_группы.cfe` — проверенное расширение.
- `extension/TeMa_HTTPСервис.Module.bsl` — исходный модуль HTTP-сервиса.
- `extension/nomenclature-group.patch` — изменения относительно ранее установленного модуля.
- `manifest.json` — размеры и контрольные суммы выгрузки и расширения.

## Получение и восстановление

1. Установить Git LFS, клонировать репозиторий и выполнить `git lfs pull`.
2. В этой папке выполнить `powershell -NoProfile -File .\Restore-Dump.ps1`. Скрипт проверит все части и соберёт `restored/InfoBase26-2026-10-26.dt`, после чего проверит SHA-256 всей выгрузки. Исходные части сохраняются. Если вместо части получен небольшой текстовый файл с `version https://git-lfs.github.com/spec/v1`, содержимое LFS ещё не скачано.
3. Создать **новую пустую файловую базу** на платформе 1С 8.3.27.1936 или совместимой более новой версии.
4. В Конфигураторе новой базы выбрать **Администрирование → Загрузить информационную базу** и указать собранный `.dt` из папки `restored`. Загрузка заменяет содержимое выбранной базы.
5. При первом запуске обозначить восстановленную базу как копию и проверить настройки обменов перед их использованием.
6. В разделе расширений проверить наличие `ИнтеграцияAmoCRM`. Выгрузка базы содержит установленные расширения; отдельный CFE приложен также для установки в другую совместимую базу.

Пароли и токены подключения не перечислены в инструкции. Выгрузка содержит данные информационной базы; сохранять её в приватном репозитории.

## Проверенное исправление

В `ГенерацияУПДСоздатьУПД` группа из `Номенклатура.НоменклатурнаяГруппа` переносится в `РеализацияТоваровУслуг.Товары.Субконто`. При пустой группе API возвращает `400` до записи реализации. Удалено обращение к отсутствующему в этой конфигурации реквизиту `УчитыватьНДС`.

Проверка 23.10.2026 в исходной тестовой копии:

- АМО-0000008 создан и проведён через API; группа «ПРОПАН» подтверждена в строке и проводках 90.01.1 и 90.02.1.
- В АМО-0000009 сохранены разные группы двух товаров; проведение отклонено из-за нулевого остатка второго товара.
- Заказ с пустой группой во второй строке вернул `400`; число реализаций до и после запроса не изменилось.
- Синтаксическая проверка серверного кода и внешнего соединения пройдена.

Тестовые документы оставлены в копии. Исторические реализации автоматически не исправлялись.
