# Проверка исправления номенклатурной группы

Дата: 26.10.2026, Asia/Krasnoyarsk.
Проверен коммит `75226cd` ветки `codex/test-1c-2026-10-26`.

## Вывод

Исправление переносит номенклатурную группу из карточки каждого товара в `РеализацияТоваровУслуг.Товары.Субконто`. Для проведённой реализации подтверждено заполнение аналитики по счетам **90.01.1 и 90.02.1**. В проверенных сценариях регрессий не обнаружено; менять код расширения не потребовалось.

Подтверждено для товара «Газ сжиженный углеводородный» и группы **«Основная номенклатурная группа ПРОПАН»**. В документе с двумя разными товарами сохраняются две разные группы, то есть группа не назначается всем строкам одним общим значением.

Есть намеренное изменение поведения: если группа не заполнена в карточке хотя бы одного товара, создание реализации отклоняется с кодом 400. Частичная реализация и запись связи с amoCRM при этом не создаются. Перед использованием исправления нужно заполнить группы у импортируемых товаров.

**Старые реализации, в том числе с 13.08.2026, это расширение автоматически не исправляет.** Для них требуется отдельная обработка с предварительным отбором документов, заполнением групп и проверкой результатов перепроведения.

## Что проверялось

- Скачаны три части выгрузки из Git LFS. Размеры и SHA-256 каждой части и собранного `.dt` совпали с `manifest.json`.
- Выгрузка восстановлена в новую отдельную базу: `1c-test-base/restored/verification`. Рабочая база `D:\1С` не использовалась.
- Платформа: **8.5.1.1522**, 32-разрядная, из `G:\1С8.5\8.5.1.1522\bin`. Это повторная проверка на предоставленной пользователем платформе, а не повторение прежнего запуска на 8.3.27.1936.
- Контрольные суммы CFE, BSL и патча совпали с манифестом.
- Исходный модуль HTTP-сервиса побайтово совпал с модулем внутри CFE.
- Установленное в восстановленной базе расширение выгружено штатной командой `/DumpConfigToFiles ... -Extension ИнтеграцияAmoCRM`. Все **пять** его BSL-модулей побайтово совпали с соответствующими модулями внутри CFE. Список и SHA-256 находятся в `installed-modules.json`.
- Штатная команда `/CheckConfig -Server -ExternalConnection -Extension ИнтеграцияAmoCRM` завершилась сообщением **«Ошибок не обнаружено»**. Результат сохранён в `extension-check.log.txt`.
- Восемь статических проверок пройдены; результат — `static-checks.json`, исполняемый скрипт — `../Verify-Extension.py`.
- Все **14 сценариев исполнения бизнес-логики на платформе 1С** пройдены; результат — `runtime-results.json`.

Большинство сценариев выполнялись с откатом транзакции. Сценарий недостаточного остатка запускался без внешней транзакции, чтобы воспроизвести штатное сохранение черновика после неуспешного проведения; созданные для него реализация, заказ, товар, группа и запись связи удалены. Восстановление исходного количества реализаций и связей проверено. В отдельной тестовой базе остаются технические следы запусков, например журнал регистрации.

## Изменения относительно приложенного патча

Изменена только функция `ГенерацияУПДСоздатьУПД`:

1. Убрано присваивание отсутствующему в этой конфигурации реквизиту `УчитыватьНДС`. Присваивание `СуммаВключаетНДС = Истина` сохранено.
2. В цикле переноса товаров добавлено чтение `Номенклатура.НоменклатурнаяГруппа` и присваивание `НовСтрока.Субконто`.
3. Добавлен отказ при недоступной или пустой группе до первой записи реализации.

По этому патчу не менялись выбор договора, организации и склада, количество и суммы, ставки НДС, счета, нумерация, проведение, сохранение черновика, расчёт версии и остальные обработчики HTTP-сервиса.

## Границы вывода

- Это не сквозной запуск из интерфейса amoCRM через опубликованный HTTP-сервис. Внешнее соединение 1С не поддерживает тип `HTTPСервисОтвет`, поэтому в проверочной обработке входной HTTP-запрос заменён JSON-строкой, а ответ — структурой с кодом, заголовками и телом. Работа с документами, карточками, регистрами, проведение и запись черновика исполнялись реальной платформой на восстановленных данных. Исходный CFE не изменялся.
- Отдельно от этого стенда исходное установленное расширение прошло штатную проверку 1С.
- Старая версия модуля восстановлена обратным применением приложенного патча, а не получена из независимо сохранённого старого CFE. Утверждение о неизменности остального кода относится именно к этому патчу. Сравнения со старой рабочей установкой не выполнялось.
- Все возможные ветви обмена, параллельные запросы, все варианты договоров, складов и налоговых режимов не проверялись. Нулевой риск для всей интеграции этим прогоном не доказывается.
- Исторические документы не изменялись, установка в рабочую базу не выполнялась.

## Артефакты и повторение

- `../Verify-Extension.py` — статические проверки без исполнения BSL; запуск обычным Python 3 из любой папки.
- `RuntimeTests.bsl` — исходник сценариев, включая проверки и очистку фикстур.
- `prepare_harness.py` — сборка XML-исходников проверочной обработки в `../restored/harness`; читает исходный HTTP-модуль из `../extension`, вносит только адаптацию ввода/вывода и добавляет тесты.
- `runtime-results.json`, `static-checks.json`, `installed-modules.json`, `extension-check.log.txt` — результаты.
- Локально собранная обработка: `../restored/ПроверкаAmo.epf`. Для её вызова через внешнее соединение в этой сессии использовались локальные `../restored/Connect-1C.ps1` и `../restored/Ping.ps1`. Пароль в файлы не сохранялся, данные входа передавались через переменные среды процесса.

Повторять сценарии следует только в отдельной тестовой копии. Зафиксированный тестовый `amo_id` предварительно проверяется на отсутствие; если он уже занят, стенд прекращает запуск.
