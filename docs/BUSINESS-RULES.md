# Цена, НДС, аналитика и договор

## Как трактуется цена

В текущем виджете `price` — цена **с НДС**. Даже при выборе ставки `НДС20` виджет выделяет налог из общей стоимости. Цена без НДС с начислением налога сверху отдельным режимом не реализована.

| Значение | Поле JSON | Поле заказа 1С |
| --- | --- | --- |
| Количество | `quantity` | `Количество` |
| Цена с НДС | `price` | `Цена` |
| Сумма без НДС | `sum` | `Сумма` |
| НДС | `vat_sum` | `СуммаНДС` |
| Итог с НДС | `total` | `Всего` |

Пример: **100 × 23 = 2300**, ставка 22/122. НДС — **414,75**, сумма без НДС — **1885,25**. Заголовок заказа, счёта, УПД и спецификации договора должен сохранять экономический итог 2300.

В счёте и реализации установлен признак `СуммаВключаетНДС = Истина`. Поэтому их строковое поле `Сумма` заполняется из **`Всего` заказа**, а не из `Сумма`. Это выполняет `TeMa_СуммаСтрокиСНДС`: возвращает округлённое до двух знаков `Всего`, сохраняя переданный итог. Ранее перенос суммы без НДС при включённом признаке НДС уменьшал документ с 2300 до 1885,25.

После проведения контрольного примера ожидаются расчёты с покупателем 2300, НДС 414,75 и выручка без НДС 1885,25. Проверять нужно и документы, и движения. Цена/суммы JSON должны быть согласованы: исправление переноса не заменяет полноценную серверную проверку всех некорректных комбинаций входных значений.

## Номенклатурная группа

Для каждой строки реализации берётся `Номенклатура.НоменклатурнаяГруппа` и записывается в `Товары.Субконто`. Разным товарам могут соответствовать разные группы. Если группа пуста, API возвращает 400 до первой записи реализации. Пустая строка номенклатуры пропускается; полностью пустой состав товаров отклоняется.

Для контрольного товара группа ПРОПАН проверена в строке и аналитике счетов 90.01.1 / 90.02.1. При нехватке остатка возможен ответ 202: документ сохранён как черновик с причиной отказа проведения. Наличие документа ещё не означает успешного проведения.

## Выбор договора

Общий алгоритм `TeMa_ДоговорЗаказа` используется для счёта и УПД:

1. Явный непустой `contract_id`, если передан.
2. Сохранённая ссылка в заказе.
3. Для старого заказа со строкой — договор через регистр связей с amoCRM, начиная с последней версии.
4. Договор покупателя с именем «Без договора», затем подходящий договор по коду.

Договор должен существовать, принадлежать покупателю заказа, иметь вид `СПокупателем` и не быть помеченным на удаление. Некорректный, отсутствующий или чужой явный `contract_id` приводит к 400 до создания реализации: молча заменять его другим договором нельзя.

Поле заказа `Договор` имеет составной тип: **ссылка на ДоговорыКонтрагентов + прежняя строка длиной 10**. Это позволяет сохранять ссылку нового договора и сохраняет совместимость со старыми строковыми значениями. Старая обрезанная строка не используется как надёжный идентификатор договора.

## Уже созданные документы

Установка расширения не пересчитывает старые счета, УПД, проводки и ранее выгруженные PDF. Для исправления истории нужны отдельный отбор, резервная копия, согласование периода и контроль перепроведения. Подтверждения завершённого исправления пользовательской цепочки в сохранённых артефактах нет.
