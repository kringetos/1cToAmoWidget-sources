# Передача исходников

## Состав

`python tools/prepare_sources.py` формирует `deliverables/1c-amocrm-2026-11-23` по явному списку:

- Документация и инструмент подготовки комплекта.
- Исходники React, файл зависимостей с lock-файлом, Vite-конфигурация и ресурсы оболочки amoCRM.
- Полная XML-выгрузка исправленного расширения и готовый CFE с исходным манифестом.
- Старый CFE, модуль и патч для сопоставления, исходная инструкция восстановления и манифест базы без самой базы.
- Исходники и результаты проверок, включая XML/BSL проверочной обработки `PriceTestAmo`, если они доступны локально.
- Python-заготовка backend, явно обозначенная как незавершённая.

Не включаются `.git`, `node_modules`, выгрузки `.dt` и их части, каталоги файловых баз, журналы/скриншоты стенда, аудит конкретной пользовательской цепочки, локальные скрипты её изменения и секреты подключения. Исходники типовой конфигурации и экспорт workflow n8n в этом репозитории отсутствуют.

## Сборка устанавливаемого виджета

```powershell
Set-Location 'deliverables/1c-amocrm-2026-11-23/frontend'
npm ci
npm run build
```

Это формирует новый `widget.zip` из передаваемых исходников. При повторной сборке побайтовый ZIP может отличаться из-за времени файлов; контрольные суммы относятся к конкретному собранному комплекту.

Из корня проекта после сборки:

```powershell
python tools/prepare_sources.py --finalize
```

Команда проверяет исходный манифест CFE и пяти BSL-модулей, наличие обязательных файлов виджета, формирует `SOURCE-MANIFEST.json` с SHA-256 каждого файла и создаёт `deliverables/1c-amocrm-2026-11-23.zip`. Установленные зависимости в архив не включаются. Подготовка комплекта не публикует его в GitHub и не устанавливает виджет.

## Повторение проверок

`python 1c-test-base/Verify-Extension.py` проверяет **старый** вариант исправления группы. Для нового варианта манифест и соответствие пяти BSL-модулей содержимому CFE проверяются инструментом подготовки комплекта. Это проверки артефактов, они не исполняют бизнес-логику.

`verification/harness/PriceTestAmo.xml` и подпапка с модулем — сохранённый исходник проверочной внешней обработки. В Конфигураторе тестовой базы соберите EPF:

```text
/LoadExternalDataProcessorOrReportFromFiles "<PriceTestAmo.xml>" "<PriceTestAmo.epf>"
```

После установки нового расширения вызовите экспортные `RunPriceTests()` и `RunAllTests()` обработки на отдельной восстановленной копии. Они возвращают JSON результатов. Пример записи через внешнее соединение: `ExternalDataProcessors.Create(<полный путь EPF>, Ложь)`. Windows COM требует совпадения разрядности клиента и платформы; регистрация COM и авторизация зависят от окружения и не включены как универсальная автоматическая настройка.

Для исходного набора группы `verification/prepare_harness.py` создаёт XML-обработку на основе старого HTTP-модуля. Не выдавайте её результат за тест исправленного CFE.

Данные и исходные объекты для тестов берутся из восстановленной базы; пустая база без конфигурации и данных для runtime-проверок не подходит.
