# HTTP API интеграции

Основание: XML маршрутов и BSL исправленного расширения в `price-contract-fix/src`. Это описание локального кода, не обещание доступности сервера. Полный список методов и обработчиков — [API-ROUTES.md](API-ROUTES.md), формируется при подготовке комплекта.

## Подключение

Префикс сервиса: `<корень публикации>/hs/integration`. Большинство бизнес-маршрутов начинаются с `/v1`; ping — `/ping`. Авторизация публикации — Basic. Пароли в примерах не приводятся.

Виджет отправляет запрос на `<n8n_url>/webhook/1c-proxy` и передаёт полный целевой URL в заголовке `X-1C-Url`. Тело и метод соответствуют запросу к 1С. Это не API Python-заготовки из `backend`.

## Основные операции

| Маршрут относительно `/hs/integration` | Назначение |
| --- | --- |
| `GET /ping` | Проверка связи |
| `GET, POST /v1/companies` | Поиск/синхронизация контрагента, поиск по `amo_id` |
| `GET /v1/nomenclature` | Поиск товара (`search`) или получение по `id` |
| `GET /v1/warehouses` | Склады |
| `GET /v1/bank_accounts` | Банковские счета |
| `GET /v1/vat-rates` | Ставки НДС и их идентификаторы |
| `GET, POST /v1/orders` | Список по `amo_id`, создание/обновление заказа |
| `GET /v1/orders/get?id=<UUID>` | Один заказ для редактирования |
| `GET, POST /v1/generate-dkp` | Список/создание договора купли-продажи |
| `GET, POST /v1/generate-invoice` | Список/создание счёта |
| `GET, POST /v1/generate-upd` | Список/создание реализации (УПД) |
| `GET /v1/dog_pros` | Договоры контрагента |
| `POST /v1/generate-dp` | Создание договора поставки |

Точные маршруты PDF и остальных операций приведены в автоматически сформированной таблице. PDF формируется сервером; виджет также содержит отправку файлов в amoCRM Drive.

**Несоответствие компонентов:** виджет вызывает `GET/POST /v1/signatories`, но в XML передаваемого расширения такой маршрут отсутствует. Управление подписантами нельзя считать поддержанным этим CFE без дополнительной серверной реализации. Остальные функции также требуют приёмки совместных версий.

## Пример заказа

Все обозначения `UUID_*` нужно заменить реальными UUID из той же тестовой базы. `amo_id` — ID сделки; `contractor_id` — UUID контрагента 1С. `id` добавляется при редактировании.

```json
{
  "amo_id": "TEST_DEAL_ID",
  "contractor_id": "UUID_CONTRACTOR",
  "warehouse_id": "UUID_WAREHOUSE",
  "bank_account_id": "UUID_BANK_ACCOUNT",
  "delivery_address": "Тестовая доставка",
  "total_sum": 2300,
  "products": [{
    "nomenclature_id": "UUID_PRODUCT",
    "quantity": 100,
    "price": 23,
    "sum": 1885.25,
    "vat_sum": 414.75,
    "total": 2300,
    "vat_rate_id": "НДС22_122"
  }]
}
```

Для создания счёта передаются `order_id` и `amo_id`; для УПД — также выбранный `contract_id`, когда договор выбирается явно. Параметры и обязательность остальных полей конкретной операции определяются её BSL-обработчиком. Повторное создание не следует считать безопасным повтором запроса: перед повтором после сетевого сбоя проверьте список и версии документов.

## Ответы и ошибки

- 200 — успешная операция; проверяйте поля ответа и документ.
- 202 при формировании УПД — сохранён черновик, проведение не выполнено; прочитайте `error_reason`.
- 400 — некорректные данные, в том числе пустая группа товара или неверный договор.
- 401 — нет подходящей авторизации публикации.
- 404 — объект или список по идентификатору не найден; отличайте JSON 1С от HTML 404 IIS.
- 500 — ошибка исполнения либо ошибка прокси; исследуйте вложенную причину.

Прокси может изменить внешний статус и обернуть ответ в массив. Число 500 на входе n8n не доказывает ошибку проведения в 1С. Сначала исследуйте исходное тело ответа и список документов, затем журнал `TeMa_ЛогиAPI`.
